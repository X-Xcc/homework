# 法律学习 AI 工作台 — 页面状态矩阵 v1

> 版本：v1  
> 日期：2026-06-10  
> 作用：把三大核心页面的 loading / empty / error / processing / success / save-error 等状态整理成前端实现与测试都可直接使用的矩阵

---

## 1. 文档目标

本文件用于回答以下问题：

1. 三大核心页面分别有哪些必须支持的页面状态？
2. 每种状态的触发条件、页面表现、可用动作分别是什么？
3. 哪些状态是页面级，哪些是局部模块级？
4. 前端实现、联调验证、测试用例设计应如何对齐？

---

## 2. 使用方式

这份矩阵建议同时给三类角色使用：

- **前端开发**：决定状态分支、组件拆分、查询与 mutation 行为
- **产品 / 设计**：确认每种状态下的反馈与动作是否完整
- **测试 / QA**：据此编写页面状态验证清单

---

## 3. 状态设计总原则

## 3.1 页面级状态与模块级状态分开

- **页面级状态**：决定整页主框架显示什么
- **模块级状态**：只影响某个区块，不应拖垮全页

### 实现原则

- 首屏加载失败时，允许整页 error
- 局部请求失败时，只降级对应模块
- AI 处理、保存、绑定关系等动作优先走局部状态

---

## 3.2 状态优先级

同一时间若多个状态同时出现，建议按以下优先级处理：

1. `page-error`
2. `initial-loading`
3. `empty`
4. `ready`
5. `partial-loading`
6. `inline-processing`
7. `inline-error`

### 原则

- 页面不可用时先保障页面级反馈清晰
- 页面可用后，再处理局部异步状态

---

## 3.3 反馈形式统一约定

| 类型 | 建议形式 |
| --- | --- |
| 页面首次加载 | Skeleton / 页面级占位 |
| 页面不可用 | 页面级错误态 |
| 区块为空 | Section Empty State |
| 提交中 | 按钮 loading / 区块 loading |
| 提交成功 | Toast + 局部刷新 |
| 提交失败 | Inline Error + Retry |
| 保存失败 | 固定状态提示 + 重试 |

## 4. 页面一：工作台首页状态矩阵

## 4.1 首页状态总览

| 状态名 | 级别 | 必须 | 说明 |
| --- | --- | --- | --- |
| `initial-loading` | 页面级 | 是 | 首次进入首页，聚合数据尚未返回 |
| `empty` | 页面级 | 是 | 新用户或无任何可展示对象 |
| `ready` | 页面级 | 是 | 首页主要内容可展示 |
| `partial-empty` | 模块级 | 是 | 某个分区无数据，但首页整体可用 |
| `partial-error` | 模块级 | 建议 | 某个分区加载失败 |
| `refreshing` | 模块级 | 建议 | 局部刷新最近对象或卡片列表 |
| `upload-submitting` | 动作级 | 是 | 上传材料动作进行中 |
| `create-case-submitting` | 动作级 | 是 | 新建案件动作进行中 |

---

## 4.2 首页状态明细

### `initial-loading`

- **触发条件**：首次进入 `/dashboard` 且 `GET /api/dashboard` 未返回
- **表现**：
  - Hero 区骨架
  - Continue 卡片骨架
  - Recent 区列表骨架
- **可用动作**：
  - 不建议展示真实业务动作
- **测试重点**：
  - 不出现布局跳闪
  - 骨架结构接近最终布局

### `empty`

- **触发条件**：首页聚合接口成功，但案件、材料、成果、知识预览均为空
- **表现**：
  - 欢迎文案
  - `上传第一份材料`
  - `创建第一个案件`
  - 简短引导说明
- **可用动作**：
  - 上传材料
  - 新建案件
- **测试重点**：
  - 空状态不显得像报错
  - 两个主动作清晰可点

### `ready`

- **触发条件**：首页主数据已成功返回
- **表现**：
  - 正常展示 Continue 区、最近对象区、知识预览区
- **可用动作**：
  - 继续案件
  - 上传材料
  - 新建案件
  - 查看最近对象
- **测试重点**：
  - 卡片点击正确跳转
  - 主动作始终可见

### `partial-empty`

- **触发条件**：某个分区数组为空，但其他分区有数据
- **表现**：
  - 空分区显示简化 empty 文案
  - 其他分区正常显示
- **可用动作**：
  - 保持页面其他动作不受影响
- **测试重点**：
  - 不误判为整页 empty
  - 空分区与正常分区共存时布局稳定

### `partial-error`

- **触发条件**：聚合接口拆分或局部刷新时，某一区块失败
- **表现**：
  - 区块内错误提示
  - 区块内 `重试`
- **可用动作**：
  - 其他区域照常可用
- **测试重点**：
  - 错误仅局限在分区内
  - 不影响页面主动作

### `upload-submitting`

- **触发条件**：用户提交上传材料表单
- **表现**：
  - 上传弹层按钮 loading
  - 禁止重复提交
  - 如有能力，显示上传进度
- **成功后**：
  - Toast：`材料上传成功`
  - 跳转材料详情页
- **失败后**：
  - 弹层内展示错误
  - 允许重试
- **测试重点**：
  - 不可重复点击
  - 失败后用户输入不丢失

### `create-case-submitting`

- **触发条件**：提交新建案件表单
- **表现**：
  - 按钮 loading
  - 表单禁用重复提交
- **成功后**：
  - 跳转案件工作区
- **失败后**：
  - 就近报错
- **测试重点**：
  - 标题必填校验
  - 成功时弹层关闭并跳转

## 5. 页面二：材料详情 / 阅读页状态矩阵

## 5.1 材料页状态总览

| 状态名 | 级别 | 必须 | 说明 |
| --- | --- | --- | --- |
| `initial-loading` | 页面级 | 是 | 首次进入材料页 |
| `processing-source` | 页面级 | 是 | 材料对象已存在，但正文仍在解析 |
| `empty-content` | 页面级 | 是 | 材料存在，但无正文可展示 |
| `ready` | 页面级 | 是 | 正文与侧栏主要信息可用 |
| `page-error` | 页面级 | 是 | 材料详情无法加载 |
| `ai-processing` | 模块级 | 是 | 某个 AI 动作正在处理 |
| `ai-partial-result` | 模块级 | 建议 | AI 已返回部分结果 |
| `ai-error` | 模块级 | 是 | 某个 AI 动作失败 |
| `relation-submitting` | 动作级 | 是 | 绑定案件 / 分析进行中 |
| `relation-error` | 动作级 | 是 | 绑定关系失败 |
| `knowledge-create-submitting` | 动作级 | 建议 | 从候选知识创建知识点 |

---

## 5.2 材料页状态明细

### `initial-loading`

- **触发条件**：首次进入 `/materials/:materialId`
- **表现**：
  - 标题骨架
  - 正文骨架
  - 右侧栏骨架
- **可用动作**：
  - 不建议展示业务动作
- **测试重点**：
  - 长文容器骨架稳定
  - 左右布局不跳闪

### `processing-source`

- **触发条件**：材料上传成功，但源文件解析尚未完成
- **表现**：
  - 正文区显示 `正在处理材料内容`
  - 元信息可读
  - AI 动作禁用或标记不可用
- **可用动作**：
  - 返回上一页
  - 等待或触发重新处理
- **测试重点**：
  - 用户知道“对象已创建但正文未就绪”
  - 不应误判成 error

### `empty-content`

- **触发条件**：材料存在，但正文为空或抽取失败后无内容
- **表现**：
  - 空内容提示
  - `重新处理`
- **可用动作**：
  - 返回
  - 重新处理
- **测试重点**：
  - 与 `processing-source` 清楚区分

### `ready`

- **触发条件**：材料标题、正文、右侧主信息可展示
- **表现**：
  - 正常阅读布局
  - 右侧显示 AI 与关系区
- **可用动作**：
  - 阅读
  - AI 提炼
  - 关联案件
  - 关联分析
  - 创建知识点
- **测试重点**：
  - 右侧刷新不影响正文滚动位置

### `page-error`

- **触发条件**：材料详情加载失败
- **表现**：
  - 页面级错误态
  - `重试`
  - `返回上一页`
- **测试重点**：
  - 错误态信息明确
  - 重试可恢复

### `ai-processing`

- **触发条件**：点击 `生成摘要`、`识别争点候选`、`提取知识候选` 等动作
- **表现**：
  - 当前动作按钮 loading
  - 当前结果区域显示处理中
  - 其他 AI 动作可按策略继续或局部禁用
- **测试重点**：
  - 仅锁定当前动作，不锁整页
  - 用户仍可继续阅读正文

### `ai-partial-result`

- **触发条件**：某些结果先返回，另一些结果未完成
- **表现**：
  - 已完成卡片可交互
  - 未完成卡片继续 loading
- **测试重点**：
  - 混合状态下排序与交互不混乱

### `ai-error`

- **触发条件**：AI 动作失败
- **表现**：
  - 对应结果区错误提示
  - `重试`
- **测试重点**：
  - 错误仅作用于对应动作
  - 其他结果不丢失

### `relation-submitting`

- **触发条件**：提交关联案件或关联分析
- **表现**：
  - 弹层确认按钮 loading
  - 禁止重复提交
- **成功后**：
  - Toast
  - 关系列表即时更新
- **失败后**：
  - 保留弹层
  - 就近错误提示
- **测试重点**：
  - 重复关联有清晰提示

### `relation-error`

- **触发条件**：绑定失败、重复绑定、目标不存在
- **表现**：
  - 表单级错误
- **测试重点**：
  - 错误语义清晰，不只写“操作失败”

## 6. 页面三：案件分析工作区状态矩阵

## 6.1 工作区状态总览

| 状态名 | 级别 | 必须 | 说明 |
| --- | --- | --- | --- |
| `initial-loading` | 页面级 | 是 | 首次进入工作区 |
| `empty-analysis` | 页面级 / 主区级 | 是 | 案件存在，但尚无分析 |
| `empty-evidence` | 模块级 | 是 | 当前分析尚未挂材料 |
| `ready` | 页面级 | 是 | 头部、树、编辑区、右栏可用 |
| `page-error` | 页面级 | 是 | 工作区加载失败 |
| `editor-dirty` | 模块级 | 是 | 编辑器有未保存修改 |
| `editor-saving` | 模块级 | 是 | 编辑器正在保存 |
| `editor-saved` | 模块级 | 是 | 编辑器保存成功 |
| `save-error` | 模块级 | 是 | 编辑器保存失败 |
| `context-switch-saving` | 模块级 | 建议 | 切换争点前自动保存 |
| `ai-processing` | 模块级 | 是 | 工作区 AI 动作处理中 |
| `ai-error` | 模块级 | 是 | 工作区 AI 动作失败 |
| `attach-material-submitting` | 动作级 | 是 | 绑定材料中 |
| `attach-knowledge-submitting` | 动作级 | 建议 | 绑定知识中 |

---

## 6.2 工作区状态明细

### `initial-loading`

- **触发条件**：首次进入 `/cases/:caseId/workspace`
- **表现**：
  - 头部骨架
  - 左侧树骨架
  - 编辑区骨架
  - 右侧栏骨架
- **测试重点**：
  - 三栏布局骨架完整
  - 不出现明显错位

### `empty-analysis`

- **触发条件**：案件存在，但无任何分析对象
- **表现**：
  - 主区空状态
  - `创建第一份分析`
  - 可附带推荐下一步
- **可用动作**：
  - 创建分析
- **测试重点**：
  - 页面不是 error
  - 主动作清晰

### `empty-evidence`

- **触发条件**：当前分析存在，但无已关联材料
- **表现**：
  - 证据区空提示
  - `添加材料`
- **测试重点**：
  - 不影响编辑器继续使用

### `ready`

- **触发条件**：案件主信息、争点树、分析上下文、右侧栏均可显示
- **表现**：
  - 正常工作区布局
- **可用动作**：
  - 创建分析
  - 编辑分析
  - 切换争点
  - 绑定材料
  - 绑定知识
  - 触发 AI
- **测试重点**：
  - 当前案件、当前争点、当前分析上下文一致

### `page-error`

- **触发条件**：案件工作区无法加载
- **表现**：
  - 页面级错误态
  - `重试`
  - `返回案件列表`
- **测试重点**：
  - 错误恢复路径清楚

### `editor-dirty`

- **触发条件**：编辑器有未保存改动
- **表现**：
  - 状态栏提示 `未保存`
- **测试重点**：
  - 输入后状态及时变化
  - 不因右栏刷新而重置

### `editor-saving`

- **触发条件**：自动保存或手动保存触发
- **表现**：
  - 状态栏提示 `保存中`
- **测试重点**：
  - 保存中仍尽量允许继续输入
  - 不产生卡顿感

### `editor-saved`

- **触发条件**：保存成功
- **表现**：
  - 状态栏提示 `已保存`
  - 更新时间刷新
- **测试重点**：
  - 状态变化清晰但不过度打扰

### `save-error`

- **触发条件**：保存失败
- **表现**：
  - 编辑器顶部或状态栏固定提示
  - 提供 `重试保存`
- **约束**：
  - 当前草稿必须保留
- **测试重点**：
  - 失败不丢内容
  - 重试路径存在

### `context-switch-saving`

- **触发条件**：当前分析有未保存内容，用户切换争点或分析上下文
- **表现**：
  - 先进入自动保存
  - 保存成功后切换
  - 保存失败则阻止切换
- **测试重点**：
  - 不悄悄丢内容
  - 切换逻辑可预测

### `ai-processing`

- **触发条件**：点击 `补全争点结构`、`生成分析提纲`、`生成结论草稿` 等动作
- **表现**：
  - 当前 AI 卡片 loading
  - 结果容器预留
- **测试重点**：
  - 不锁死整页
  - 编辑器仍可浏览或继续输入

### `ai-error`

- **触发条件**：某个 AI 动作失败
- **表现**：
  - 卡片内错误提示
  - `重试`
- **测试重点**：
  - 错误仅局部呈现

### `attach-material-submitting`

- **触发条件**：提交材料绑定
- **表现**：
  - 抽屉确认按钮 loading
- **成功后**：
  - 证据区更新
- **失败后**：
  - 抽屉保留并报错
- **测试重点**：
  - 绑定成功后材料可点击跳转

## 7. 跨页面动作状态矩阵

## 7.1 上传材料

| 动作状态 | 触发条件 | 表现 | 成功结果 | 失败结果 |
| --- | --- | --- | --- | --- |
| `idle` | 弹层打开未提交 | 可编辑表单 | - | - |
| `submitting` | 点击确认上传 | 按钮 loading，禁用重复提交 | 跳转材料页 | 保留表单并报错 |
| `success` | 上传成功 | Toast | 进入材料详情页 | - |
| `error` | 上传失败 | Inline Error | - | 可重试 |

## 7.2 新建案件

| 动作状态 | 触发条件 | 表现 | 成功结果 | 失败结果 |
| --- | --- | --- | --- | --- |
| `idle` | 弹层打开未提交 | 可编辑表单 | - | - |
| `validating` | 本地校验 | 字段提示 | 进入提交 | 保留当前表单 |
| `submitting` | 提交创建 | 按钮 loading | 跳转工作区 | 保留表单并报错 |
| `success` | 创建成功 | Toast 或直接跳转 | 进入工作区 | - |
| `error` | 创建失败 | Inline Error | - | 可重试 |

## 8. 前端实现建议映射

## 8.1 建议拆分的通用状态组件

建议至少准备：

```text
PageSkeleton
PageErrorState
SectionEmptyState
InlineError
ActionButtonLoading
EditorSaveState
```

---

## 8.2 建议拆分的状态判断层

每个页面建议拆成：

1. **页面查询态判断**
2. **ViewModel 适配**
3. **渲染分支组件**
4. **动作级 mutation 状态**

### 原因

这样能避免页面组件中充斥过多 `if/else`。

---

## 9. 测试建议映射

## 9.1 页面级测试最少覆盖

### Dashboard

- 首次加载
- 全空状态
- 正常有数据
- 单分区为空
- 上传材料失败
- 新建案件失败

### Material Detail

- 首次加载
- 正文处理中
- 正文为空
- AI 动作成功
- AI 动作失败
- 关联案件失败

### Case Workspace

- 首次加载
- 无分析
- 有分析无材料
- 保存成功
- 保存失败
- 切换上下文触发自动保存
- AI 动作失败

---

## 9.2 回归测试高风险点

优先回归：

- 编辑器保存失败后内容是否保留
- 右栏刷新是否导致正文 / 编辑区位置丢失
- 绑定关系成功后列表是否即时刷新
- 页面从 empty → ready 的切换是否稳定
- 页面从 processing → ready 的切换是否误闪 error

---

## 10. MVP 必做状态清单

以下状态建议视为 P0：

- Dashboard：`initial-loading` / `empty` / `ready`
- Material Detail：`initial-loading` / `processing-source` / `ready` / `page-error`
- Case Workspace：`initial-loading` / `empty-analysis` / `ready` / `save-error` / `page-error`
- 全局动作：上传材料 `submitting/error`、新建案件 `submitting/error`

## 11. 本阶段结论
