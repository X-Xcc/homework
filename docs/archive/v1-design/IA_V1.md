# 法律学习 AI 工作台 — 信息架构 IA v1

> 版本：v1  
> 日期：2026-06-09  
> 状态：用于定义产品骨架与主路径，后续可继续细化为 PRD / 页面结构 / 交互稿

---

## 1. IA 目标

本信息架构用于解决三个问题：

1. **这个产品到底围绕什么组织？**
2. **用户从哪里进入，如何一步步进入分析？**
3. **材料、案件、法条、知识卡、分析结果之间如何形成统一空间？**

本版本的核心结论是：

> **产品不以单个功能组织，而以“工作对象 + 分析动作 + 知识沉淀”组织。**

也就是说，这不是一个“功能菜单式 AI 工具”，而是一个围绕法律学习与分析任务展开的工作台。

---

## 2. 信息架构总原则

### 2.1 以“对象”组织，而不是以“工具”组织

用户不是为了“用摘要功能”而来，而是为了处理某份材料、某个案件、某个问题。

因此 IA 的一级组织不应是：

- 摘要
- 问答
- 笔记
- 卡片

而应是：

- 我正在处理什么
- 我能对它做什么
- 它会沉淀成什么

### 2.2 以“工作流”串联，而不是强制线性流程

主路径存在，但不僵硬。

用户可以：

- 从材料进入案件分析
- 从案件跳到法条
- 从法条跳到争点
- 从争点生成知识卡
- 从知识卡回看原始材料

所以产品需要同时具备：

- **主工作流**：帮助新用户快速上手
- **自由跳转结构**：满足进阶用户探索和复盘

### 2.3 以“沉淀”为闭环终点

如果用户只是读完、问完、看完，产品价值不完整。

闭环必须落在可复用沉淀物上：

- 案例分析结果
- 法条理解卡
- 争点卡
- 论证骨架
- 复习包

## 3. 核心对象模型

IA v1 定义 6 个一级核心对象：

1. **工作台 Workspace**
2. **材料 Material**
3. **案件/项目 Case**
4. **知识节点 Knowledge**
5. **分析结果 Analysis**
6. **沉淀成果 Collection**

它们不是并列文件夹关系，而是可相互连接的对象网络。

### 3.1 Workspace（工作台）

**定义：** 用户当前处理任务的入口与上下文容器。

**作用：**

- 承接今日任务
- 展示最近处理对象
- 提供继续分析的起点
- 汇总待完成项目、最近材料、最近卡片、推荐动作

**用户理解：**

“我现在要处理什么，从哪里继续。”

### 3.2 Material（材料）

**定义：** 原始输入内容，包括但不限于：

- 判决书
- 合同
- 法规条文
- 课堂讲义
- 学术论文
- 笔记截图 / 文档
- 实习材料

**作用：**

- 作为分析的原始依据
- 支持切片、标注、提问、摘要、引用
- 可以被挂接到某个案件/项目中

**用户理解：**

“这是我要读和拆的原始材料。”

### 3.3 Case（案件/项目）

**定义：** 一次有明确目标的分析任务容器。

可能是：

- 一个真实案件
- 一道案例分析题
- 一个课程作业主题
- 一项合规研究任务
- 一次法条比较研究

**作用：**

- 聚合相关材料
- 管理争点与分析结构
- 形成面向任务的成果输出

**用户理解：**

“这是我当前正在解决的问题。”

### 3.4 Knowledge（知识节点）

**定义：** 从材料和分析中抽出的稳定知识单位。

候选节点类型：

- 法条节点
- 概念节点
- 争点节点
- 要件节点
- 案例节点
- 规则节点

**作用：**

- 连接不同材料和案件
- 承担“知识空间感”的核心结构
- 让产品不止停留在文档处理，而具备长期积累能力

**用户理解：**

“这是我可以反复复用、反复连接的知识。”

### 3.5 Analysis（分析结果）

**定义：** 围绕某个问题生成或编辑出的中间思考产物。

典型类型：

- 争点树
- 事实梳理
- 法律关系图
- 论证骨架
- 要件匹配表
- 案例对比稿

**作用：**

- 承担 AI 协作的主要载体
- 显示思维过程，而不是只显示答案
- 支持编辑、追溯来源、导出使用

**用户理解：**

“这是我当前形成中的分析。”

### 3.6 Collection（沉淀成果）

**定义：** 为复习、复用、输出而保存的成果集合。

可能包括：

- 知识卡片库
- 案例库
- 复习包
- 答题模板集
- 高频争点集

**作用：**

- 形成长期资产
- 让学习和分析结果可回收
- 支持二次复习和二次创作

**用户理解：**

“这是我已经积累下来的东西。”

## 4. 对象关系模型

核心关系如下：

```text
Workspace
 ├─ contains → Case
 ├─ contains → Material
 ├─ surfaces → Analysis
 └─ surfaces → Collection

Material
 ├─ belongs to / links to → Case
 ├─ extracts → Knowledge
 ├─ supports → Analysis
 └─ cites into → Collection

Case
 ├─ aggregates → Material
 ├─ organizes → Analysis
 ├─ references → Knowledge
 └─ outputs → Collection

Knowledge
 ├─ derived from → Material
 ├─ referenced by → Case
 ├─ used in → Analysis
 └─ saved into → Collection

Analysis
 ├─ based on → Material
 ├─ scoped to → Case
 ├─ references → Knowledge
 └─ promoted to → Collection

Collection
 ├─ collects → Knowledge
 ├─ collects → Analysis
 └─ links back to → Material / Case
```

这意味着：

- 所有成果都能回溯来源
- 所有材料都能进入分析
- 所有知识都能被再次复用
- 用户不会丢失上下文

## 5. 一级导航设计

IA v1 推荐采用 **5 个一级导航**：

1. **工作台**
2. **材料**
3. **案件**
4. **知识库**
5. **成果**

这 5 个导航分别对应用户的 5 种心智入口。

### 5.1 工作台

**角色：默认首页 / 总控入口**

内容建议：

- 今日继续
- 最近案件
- 最近材料
- 正在形成的分析
- 新生成的知识卡
- 推荐下一步动作

用户问题：

- 我现在该从哪里继续？
- 最近做到哪了？

### 5.2 材料

**角色：输入层**

内容建议：

- 材料列表
- 上传入口
- 类型筛选
- 标注状态
- 最近阅读
- 是否已归属某案件

用户问题：

- 我要读什么？
- 这份材料处理到哪了？

### 5.3 案件

**角色：任务层 / 工作层核心**

内容建议：

- 案件/项目列表
- 按课程 / 类型 / 进度分组
- 每个案件下的材料、争点、分析、输出

用户问题：

- 我正在解决哪些问题？
- 每个问题目前进展如何？

### 5.4 知识库

**角色：认知层核心**

内容建议：

- 法条节点
- 概念节点
- 争点节点
- 关系浏览
- 标签 / 学科 / 来源筛选

用户问题：

- 这个知识点和什么相关？
- 我已经积累了哪些可复用知识？

### 5.5 成果

**角色：闭环输出层**

内容建议：

- 知识卡
- 复习包
- 案例总结
- 论证模板
- 导出历史

用户问题：

- 我最终留下了什么？
- 我可以拿什么去复习、答题、复用？

## 6. 首页 / 工作台结构

首页不建议做成传统营销首页，而应做成 **登录后工作台首页**。

### 6.1 首页目标

首页需要在短时间内同时传达：

- 这是个有用的分析工具
- 这是个沉浸式知识工作台
- 我可以立刻开始 / 继续任务

### 6.2 首页结构建议

#### 模块 1：继续处理中

展示：

- 最近案件
- 最近材料
- 最近分析稿
- 最近生成卡片

作用：

- 降低重新进入成本
- 让用户立即回到工作状态

#### 模块 2：开始新任务

入口：

- 上传材料
- 新建案件/项目
- 从法条/主题开始探索

作用：

- 给新用户明确起点
- 给老用户新的工作入口

#### 模块 3：知识空间预览

展示：

- 最近活跃知识节点
- 争点连接
- 法条关联
- 案例网络片段

作用：

- 提前感知“不是普通 AI 聊天工具”
- 强化探索平台认知

#### 模块 4：成果沉淀

展示：

- 本周新卡片
- 最近复习包
- 最近导出成果

作用：

- 强化闭环价值
- 让用户看到长期积累

## 7. 主路径设计

IA v1 的推荐主路径是：

```text
进入工作台
→ 上传 / 打开材料
→ 归入某个案件（或创建案件）
→ 进行标注与提问
→ 形成分析结构
→ 抽取知识节点
→ 沉淀为成果
→ 回到工作台继续下一轮
```

### 7.1 新用户主路径

```text
工作台首页
→ 上传第一份材料
→ AI 初步拆解
→ 建议创建案件/主题
→ 生成初版争点/分析框架
→ 抽取首批知识卡
→ 保存到成果区
```

目标：

- 让用户在首次体验中同时看到：读材料、做分析、沉淀知识

### 7.2 老用户主路径

```text
工作台首页
→ 继续某个案件
→ 查看上次分析
→ 增补新材料
→ 修订争点/论证
→ 更新知识卡与成果
```

目标：

- 让产品成为长期工作台，而不是一次性工具

## 8. 关键页面层级

### 8.1 材料详情页

建议分为 4 个区域：

1. 原文阅读区
2. 标注 / 提问区
3. AI 分析侧栏
4. 关联对象区（所属案件 / 相关法条 / 相关知识卡）

### 8.2 案件详情页

建议分为 5 个区域：

1. 案件概览
2. 材料清单
3. 争点结构
4. 分析工作区
5. 成果沉淀区

### 8.3 知识节点详情页

建议分为 4 个区域：

1. 节点定义
2. 关联法条 / 案例 / 材料
3. 相关争点
4. 已沉淀成果

### 8.4 成果详情页

建议分为 4 个区域：

1. 成果内容
2. 来源追溯
3. 可编辑结构
4. 导出 / 加入复习包

## 9. 搜索与探索机制

为了满足“平台感”和“知识空间感”，IA 不能只有列表，还要有探索机制。

### 9.1 搜索入口

支持按以下对象统一搜索：

- 材料
- 案件
- 法条
- 概念
- 争点
- 成果

### 9.2 探索入口

除搜索外，提供探索模式：

- 相关争点推荐
- 相似案例推荐
- 相关法条联动
- 从一张卡回到原材料
- 从一个法条跳到多个案件

### 9.3 目标

搜索回答的是：

- 我想找什么？

探索回答的是：

- 我还应该看到什么？

## 10. IA 对四层定位的承接

### 功能层：法律/合规效率工具

由以下结构承接：

- 材料页
- 案件页
- 分析页
- 成果页

表现为“能做事”。

### 认知层：AI 驱动的知识探索平台

由以下结构承接：

- 知识库
- 关系连接
- 跨对象跳转
- 探索模式

表现为“能不断发现与连接”。

### 工作层：案件与材料分析工作台

由以下结构承接：

- 工作台首页
- 案件容器
- 材料到分析的主路径

表现为“能承载完整工作”。

### 体验层：未来感、沉浸式知识产品

由以下结构承接：

- 首页呈现方式
- 知识空间预览
- 动态关系可视化
- 沉浸式阅读与分析布局

表现为“有体验记忆点”。

---

## 11. IA v1 的关键拍板

本版本默认拍板如下：

1. **核心对象采用多对象模型**，不是单一“聊天”模型
2. **首页采用工作台首页**，不是营销落地页优先
3. **案件/项目是主任务容器**
4. **材料是输入入口，知识库是长期积累入口**
5. **成果区必须独立存在**，不能埋在分析页里
6. **探索机制必须与列表结构并存**
