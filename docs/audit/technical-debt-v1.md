# 技术债清单 v1

## 1. 文档目的

将当前项目中影响安全、稳定性、可维护性和交付质量的问题转化为可排序、可分期处理的清单。

## 3. 分类明细

### 3.1 安全
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| CORS 全开放 | 高 | 正式环境暴露面过大 | 按环境配置允许源 |
| 上传安全不足 | 高 | 可能引入恶意文件与路径风险 | 增加白名单、MIME 校验、隔离存储、清理策略 |
| 无速率限制 | 中 | 可能导致接口滥用、成本上升 | 对问答、分析、对比接口加限流 |
| 敏感配置管理不完整 | 中 | 密钥泄漏风险 | 明确 `.env.example` 与实际环境分离规则 |

### 3.2 鉴权
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| `X-User-Id` 可伪造 | 高 | 用户身份不可信 | 改为 token 或 session 体系 |
| `X-Client-Id` 匿名模型仅适合演示 | 高 | 无法满足正式交付 | 第一版直接切换到自注册账号体系，不再保留匿名作为正式边界 |
| `/login` 不是真正登录 | 高 | 无密码、无签名、无会话 | 设计正登录流程 |
| 权限边界薄弱 | 中 | 后续管理功能难扩展 | 第一版至少建立 `user` / `admin` 两类角色边界 |

### 3.3 数据层
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| SQLite 默认作为主库 | 高 | 并发、迁移、交付受限 | 升级 PostgreSQL |
| 无 Alembic | 高 | schema 演进不可控 | 引入迁移机制 |
| legacy schema 补丁逻辑存在 | 中 | 维护复杂、历史包袱 | 用正式迁移替代运行时修补 |
| 收藏无唯一约束 | 中 | 数据重复风险 | 增加数据库约束 |

### 3.4 AI 可靠性
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| 结构化结果依赖模型严格返回 JSON | 高 | 一旦格式漂移就影响主流程 | 增强解析兜底与降级策略 |
| 问答/分析错误处理偏直接 | 中 | 用户看到原始错误文本 | 统一 AI 异常包装 |
| 缺少模型调用日志与指标 | 中 | 成本与问题难追踪 | 增加调用日志、耗时、失败率统计 |

### 3.5 测试
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| 没有 `tests/` 体系 | 高 | 无法证明质量 | 按核心链路补单元/接口/集成测试 |
| 无自动化回归门槛 | 高 | 改动风险大 | 在 CI 中纳入 pytest |
| OCR / AI 行为缺少稳定测试 | 中 | 复杂能力回归难发现 | 补关键样例测试 |

### 3.6 部署
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| 无 Dockerfile / Compose | 高 | 环境复现难 | 提供容器化部署 |
| 无 CI/CD | 中 | 质量门槛弱 | 建立基础 GitHub Actions |
| 缺少备份恢复方案 | 中 | 交付说服力不足 | 形成可说明方案 |

### 3.7 文档
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| 缺少架构/数据库/API/测试/验收文档 | 中 | 验收与交接困难 | 按当前文档骨架逐步补齐 |
| 配置说明仍偏 README 级别 | 中 | 新人上手成本高 | 第 2 周补环境配置说明 |

### 3.8 前端维护性
| 问题 | 风险等级 | 影响 | 建议 |
|---|---|---|---|
| `frontend/js/app.js` 文件过大 | 中 | 修改风险大、可读性弱 | 分拆为 API / 状态 / 页面模块 |
| 视图逻辑与请求逻辑耦合 | 中 | 后续演进困难 | 做轻量模块化治理 |
| 错误提示与状态控制较分散 | 低 | 用户体验不稳定 | 统一 loading / error / empty 状态 |

## 4. P0 / P1 优先事项

### P0（必须尽快处理）
1. 正式认证鉴权替代伪身份头
2. PostgreSQL + Alembic 迁移
3. 上传安全与 API 规范化
4. CORS 与敏感配置治理
5. 核心链路基础测试补齐

### P1（应在本期前半段处理）
1. AI 结果解析与异常治理
2. 日志体系与健康检查增强
3. Docker 化与基础 CI
4. 前端脚本轻量模块化治理

## 5. 当前最影响交付质量的三大问题

1. **身份体系不可信**：这决定了系统目前更像演示原型，而不是正式系统。
2. **数据库与迁移机制不正规**：这会直接限制后续交付、部署与维护。
3. **缺少测试与部署体系**：即使功能可运行，也难以证明质量与可交付性。

## 6. 建议下周优先推进方向

- 先完成配置治理与环境说明
- 明确数据库升级方案
- 给认证鉴权改造做技术路线选择
- 将当前技术债映射到 12 周计划中的具体周次
